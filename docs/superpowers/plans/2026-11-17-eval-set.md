# Evaluation Set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A script that runs a checked golden set of questions through the real answer pipeline and prints retrieval and answer scores per run, saved for comparison.

**Architecture:** Pure code in `app/evals/` (golden-set loader, scoring, summary) with unit tests; one module that creates and always deletes temporary eval workspaces; a thin CLI `scripts/run_eval.py` that calls `draft_answer` (the API's own pipeline). Data lives in `backend/evals/`.

**Tech Stack:** Python 3.13, psycopg 3, pytest, pymupdf (trap PDFs), existing Ollama client.

**Spec:** `docs/superpowers/specs/2026-11-17-eval-set-design.md`

## Global Constraints

- Commands run from `backend/` with `set -a; . ./.env; set +a` and `PYTHONPATH=. ../.venv/bin/python ...`.
- Every commit step: show the user the files and message and **wait for "yes"** (CLAUDE.local.md). No `Co-Authored-By` lines. Never push.
- The eval calls `draft_answer` from `app/services/chat.py`; it never copies pipeline code.
- k defaults to 5 (`DEFAULT_K`).
- Eval workspaces are named `eval:<set>` and owned by test user A (`TEST_USER_A_EMAIL`); none may exist after a run.
- `backend/evals/docs/` is gitignored (real PDFs are not published). `golden.jsonl` and `results/` are committed.
- Keyword matching is case-insensitive substring matching.

## Review Focus

1. **Run interrupted (Ctrl+C or crash) mid-way** → eval workspaces are still deleted. Test in Task 4 (`test_workspaces_deleted_when_block_raises`).
2. **A previous run was killed hard and left `eval:*` workspaces** → the next run removes them first, and the personal workspace stays `workspaces[0]` for the tests. Test in Task 4 (`test_leftover_eval_workspaces_removed_on_start`).
3. **Ollama not running** → the runner stops with one clear line before creating any workspace. Verified in Task 5, Step 4.
4. **A typo in golden.jsonl** (bad JSON, unknown set, missing field, `expect: answer` without pages) → error naming the line number, before any work. Tests in Task 1.
5. **`evals/docs/ethics.pdf` missing** → error naming the path and where to copy it from. Test in Task 4 (`test_missing_document_file_names_the_path`).

### Task 2: Scoring one question

**Files:**
- Create: `backend/app/evals/scoring.py`
- Test: `backend/tests/test_eval_scoring.py`

**Interfaces:**
- Consumes: `Question` (Task 1); `SearchHit` (`app/services/retrieval.py`: `.filename`, `.page`, `.score`); `ParsedAnswer` (`app/rag/citations.py`: `.text`, `.cited`, `.refused`).
- Produces: `Scores` frozen dataclass: `hit: bool, rr: float, refused: bool, citation_ok: bool, keywords_ok: bool, correct: bool, failed: tuple[str, ...]` (names of the rules that failed, e.g. `("retrieval", "keywords")`).
- Produces: `score_question(q: Question, hits: list[SearchHit], parsed: ParsedAnswer) -> Scores`.

Rules (spec, "Scores per question"). A hit is "on target" when `hit.filename == q.file and hit.page in q.pages`.
- `hit`: any hit on target. `rr`: `1 / (index + 1)` of the first on-target hit, else `0.0`.
- `citation_ok`: not refused, `cited` non-empty, and every `hits[n-1]` is on target.
- `keywords_ok`: every `must_contain` group has at least one alternative in `parsed.text.lower()`, and no `must_not_contain` term appears.
- `expect == "answer"`: `correct = not refused and citation_ok and keywords_ok`. `expect == "refuse"`: `correct = refused`; `hit`, `rr`, `citation_ok`, `keywords_ok` are reported as `False/0.0` and ignored in summaries.
- `failed` lists, in this order, whichever apply: `"retrieval"` (answer, not hit), `"false_refusal"`, `"citation"`, `"keywords"`, `"not_refused"` (refuse, answered).

- [ ] **Step 1: Write the failing tests.** Helper `hit(filename, page, score=0.8)` builds a `SearchHit` with dummy ids/text. Tests:
  - `test_correct_answer_scores_everything_true`: q pages (10,11), hits pages [3,10,11], parsed cited [2], text contains "informed" and "risk" → `hit` True, `rr == 0.5`, `correct` True, `failed == ()`.
  - `test_right_page_in_another_file_is_not_a_hit`.
  - `test_retrieval_miss_gives_rr_zero_and_names_retrieval`.
  - `test_citation_to_wrong_page_fails_citation`.
  - `test_refused_answer_question_is_false_refusal_and_citation_not_ok` (Review: refused answers can't have valid citations).
  - `test_keyword_group_accepts_any_alternative_case_insensitive`: text "INFORMED users… Risk" passes `[["consent","informed"],["risk"]]`.
  - `test_must_not_contain_fails_keywords` (the D2 shape: "Yes, the gas will put out the fire [2]").
  - `test_refuse_question_correct_only_when_refused`: refused → correct, `failed == ()`; answered → `failed == ("not_refused",)`.

- [ ] **Step 2: Run, expect FAIL.**
- [ ] **Step 3: Implement `score_question`.**
- [ ] **Step 4: Run, expect PASS.**
